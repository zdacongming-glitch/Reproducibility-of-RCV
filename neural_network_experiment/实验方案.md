**1. 固定一个训练配置**

先固定一组外层训练配置：

```text
n_total
lambda
r_train
threat_model
replication_id
```

例如：

```text
n_total = 1000
lambda = 1.0
r_train = 0.1
threat_model = linf
replication_id = 3
```

这里 `r_train` 是训练时使用的鲁棒半径，决定 `AT` 和 `SR` 怎么训练。

`r_eval` 暂时不参与训练配置。

**2. 生成一次数据**

在这个固定配置下，只生成一次数据：

```text
train/CV dataset: size n_total
test dataset: size n_total
```

两份数据来自同一个 teacher 和同一个 DGP，但彼此独立。

也就是说，对于同一个：

```text
(n_total, lambda, r_train, threat_model, replication_id)
```

无论后面要评估多少个 `r_eval`，都使用同一份：

```text
D_train_cv
D_test
```

这样不同 `r_eval` 下的结果才具有可比性。

**3. 在 train/CV 数据上做 SR-CV**

接着在 `D_train_cv` 上做 repeated holdout SR-CV。

比如当前 CV 内部 train ratio 是 `0.3`，validation ratio 是 `0.7`。每次 CV split：

```text
D_train_cv -> D_inner_train + D_inner_val
```

对每个候选 procedure：

```text
erm
at
sr
core_only
```

都在 `D_inner_train` 上训练，然后在 `D_inner_val` 上计算 SR-CV 分数。

这里需要注意：SR-CV 的 validation 半径应该对应某个 selection radius。如果我们仍然希望“选择结果随 `r_eval` 变化”，那么可以在每个 `r_eval` 下重新计算 SR-CV score，但训练数据 split 和随机扰动应尽量复用。

更清晰地说，有两种选择。

第一种是固定 selection radius：

```text
r_cv = r_train 或某个指定半径
```

这样每个外层训练配置只选择一次 procedure，选择结果不随 `r_eval` 变化。

第二种是让 selection radius 等于 evaluation radius：

```text
r_cv = r_eval
```

这样对于同一批已经训练好的 candidate models，可以在不同 `r_eval` 下分别计算 SR-CV 分数，从而得到不同 `r_eval` 下的 selected procedure。

对于 phase diagram，我更建议第二种，因为 phase diagram 本来就是看 `(lambda, r_eval)` 上 SR-CV 会选哪个 procedure。

**4. 用完整 train/CV 数据训练四个最终模型**

在同一份 `D_train_cv` 上，训练四个最终模型：

```text
f_erm
f_at
f_sr
f_core_only
```

训练配置固定：

```text
r_train
threat_model
epochs
patience
model architecture
optimizer
```

关键点是：这四个模型只训练一次，不随 `r_eval` 改变。

也就是说：

```text
f_erm, f_at, f_sr, f_core_only
```

是这个外层配置和 replication 下的固定对象。

**5. 在同一个 test set 上扫所有 r_eval**

现在拿同一个 `D_test`，依次评估所有 `r_eval`：

```text
r_eval in {0.0, 0.02, 0.05, 0.1, 0.2, ...}
```

对于每个 `r_eval`，构造对应的 evaluation threat model：

```text
linf radius = r_eval
```

或：

```text
l2 radius = r_eval
```

然后对同一批模型计算：

```text
clean MSE
stochastic robust MSE at r_eval
adversarial robust diagnostic MSE at r_eval
```

这里真正变化的只有 evaluation perturbation radius，而不是数据、模型或训练随机性。

因此 `risk vs r_eval` 曲线的含义变成：

```text
同一个训练好的模型，在测试扰动半径变大时，风险如何变化
```

这才是通常意义上的 robust risk curve。

**6. 对 SR-CV selection 也扫 r_eval**

如果 phase diagram 的目标是展示：

```text
SR-CV 在不同 lambda 和 r_eval 下选择哪个 procedure
```

那么在每个 `r_eval` 下，还需要计算一次 SR-CV score：

```text
CV_SR(f_erm; r_eval)
CV_SR(f_at; r_eval)
CV_SR(f_sr; r_eval)
CV_SR(f_core_only; r_eval)
```

然后选择分数最小的 procedure。

但这里有一个关键改进：**训练好的候选模型不变，只是 CV scoring 的扰动半径变了**。

严格地说，如果 CV 是为了模拟“用训练集重新训练，然后用 validation 选择 procedure”，那么每个 CV split 内部仍需要训练 split-specific 模型。但在不同 `r_eval` 之间，也应该复用同一批 split-specific 训练模型，然后只重新计算 validation score。

也就是说，在每个 replication 内：

```text
for each CV split:
    train four procedures once under r_train
    for each r_eval:
        compute SR-CV validation score under r_eval
```

而不是：

```text
for each r_eval:
    for each CV split:
        train four procedures again
```

这会更快，也更减少不同 `r_eval` 之间的无关噪声。

**7. 输出一行结果**

最终输出时，仍然可以每个 `r_eval` 一行，但这些行共享同一组数据和模型。

每一行可以包含：

```text
n_total
lambda
r_train
r_eval
threat_model
replication_id
procedure
clean_mse
stochastic_robust_mse
selected_procedure_srcv
cv_selected_srcv_score
oracle_best_procedure
```

但注意，这些行之间的关系变了：

```text
同一个 replication_id + n_total + lambda + r_train + threat_model
```

下面的不同 `r_eval` 行，不再是独立重新训练出来的结果，而是同一训练结果在不同评估半径下的表现。

**8. 这个逻辑带来的直接好处**

第一，`core_only` 曲线应该稳定。

因为攻击只动 `X_frag`，而 `core_only` 不使用 `X_frag`，所以在同一个模型和同一个 test set 上：

```text
stochastic robust MSE(r_eval) ≈ clean MSE
```

它不应该随着 `r_eval` 明显变化。

第二，risk curves 更可解释。

以前的曲线混合了：

```text
评估半径变化
数据重采样噪声
训练随机性
CV split 随机性
```

现在主要反映：

```text
评估半径变化
```

第三，phase diagram 更平滑。

因为同一行/同一列里的很多随机性被固定住了，procedure switch 更容易解释为 `lambda` 和 `r_eval` 的影响，而不是 Monte Carlo 抖动。

第四，运行速度可能更快。

原来是：

```text
每个 r_eval 都重新训练四个 procedure
```

现在是：

```text
每个 r_train 训练四个 procedure 一次，然后扫所有 r_eval
```

尤其当 `eval_radii` 很密时，节省很明显。
